4. 网页向 SDK 传什么，剪切板到底存什么

下面四种是本项目定义的固定入口，不是 Singular 自动创建的参数。entry 只选择预先审核的广告策略，不证明实际投放来源。UTM / WP 参数用于来源统计，二者不能混为一谈。

网页入口客户端策略SDK passthrough
/block/?entry=one-clipboardfirst_ad_1block_startup_v1:clipboard
/block/?entry=two-clipboardfirst_ad_2block_startup_v1:clipboard
/block/?entry=one-ordinaryfirst_ad_1block_startup_v1:ordinary
/block/?entry=two-ordinaryfirst_ad_2block_startup_v1:ordinary

示例：两次广告的剪切板入口，用户在 iPhone 上点击 App Store 按钮，网页同步调用：

const target = 'blockdoku-bdki://startup?policy=first_ad_2&v=1';
const link = singularSdk.buildWebToAppLink(
  实际专用baselink,
  target,                         // 已安装打开目标
  'block_startup_v1:clipboard',    // 入口标记
  target                          // 首次安装后的目标
);
const destination = singularSdk.enrichUrlWithClipboardDdlFlow(link);
// 按钮 href 更新为 destination；保持 target="_blank"。

剪切板数据由 SDK 创建，不由我们拼 JSON 或复制 target 字符串。官方说明 SDK 生成 token、写入剪切板并将 ecid 附到链接；手机 SDK 再据此匹配和取得延迟链接。调用必须发生在点击事件内。页面会显示剪切板用途并允许取消；取消后使用普通标记。官方剪切板流程和限制、官方方法签名

代码不会读取或记录用户剪切板，不人工生成 token。函数返回链接只说明调用返回，不证明复制成功。用户覆盖剪切板、拒绝粘贴或网络失败，均可能无法恢复策略。客户端收到 clipboard 标记也只代表该入口选择了剪切板流程，不能当成成功匹配凭证。

6. 客户端同步与验收

本项目源码已支持 blockdoku-bdki://startup?policy=first_ad_1&v=1 和 first_ad_2。当前配置仍关闭；后续将 Assets/Resources/ProductInstallSource.json 的 mode 改为 clipboard、linkDomain 填真实域名后重新打包。此模式也接收普通延迟链接。不要把测试菜单的“手动读取剪切板”当成 Singular 安装归因。

首次安装、有效延迟回调、原启动收集窗口内才应用。剪切板入口优先，普通延迟入口其次；没有数据、错误数据、超时或老安装继续原云控及兜底。地区封顶、原关闭广告和初始化失败等保护仍优先。入口“2 次”不保证一定展示两次：地区策略、无填充等仍会限制。

  1. 网页：开发者工具 Network 查看官方 1.4.8 SDK 和初始化请求；document.documentElement.dataset.singularState 应为 ready。disabled 是尚未启用，ready 仅表示 SDK 初始化回调。
  2. 在同一台 iPhone 的 Safari 打开测试入口；点击前不写剪切板。点击 App Store 后新标签页链接应包含 SDK 生成的参数。singularLastAction=clipboard_requested 只记录调用尝试，不表示成功归因。
  3. 安装重新打包的测试应用，正常处理系统粘贴提示，期间不要复制其他内容。观察 INSTALL_SOURCE_CALLBACK deferred=True result=received policy=first_ad_1/first_ad_2，再核对启动冻结后的实际策略。
  4. 重复测试两种次数、普通方式、取消剪切板、错误入口、无参数入口、SDK 被拦截和网络超时。页面不得卡住，原商业化不得被无效输入覆盖。
  5. Singular 后台核对测试设备安装与来源。测试网页点击、原生 SDK 回调、后台实际接收分别记录；没有接收证据不能写“归因通过”。

官方剪切板 FAQ 描述的是商店安装流程，没有给出 TestFlight 完整归因保证。TestFlight 先做经客户经理确认的联调；正式商店安装再验收整条链路。官方支持边界

7. Mintegral 投放入口怎么放

本轮只准备网站参数，不修改 Mintegral campaign。可用测试网页地址：https://www.scltdhk.com/block/?entry=two-clipboard&utm_source=mintegral&utm_campaign=block_web_test_2。其中 campaign 是本项目建议的联调名称，不是已存在投放。正式 click ID、宏和渠道追踪链接必须让 Singular / Mintegral 确认，不能靠手填 utm_source 冒充广告平台点击。

网页 SDK 把页面的 UTM/WP 信息传到专用链接，真正归因仍由 Singular 处理。页面本身不会因为名字含 mintegral 就认定付费用户。官方参数传递与报表说明
